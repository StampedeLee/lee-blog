## 什么是Agent？
(体现面试优势)

### 1.1 从LLM到单Agent

**从LLM的问答，到端到端地去帮助人完成一个复杂的任务**

Agent = LLM + Plan + Memory + Tool

### 1.2 从单agent到多agent
大模型的实现机制是：**Attention 注意力机制**，但上下文的注意力是有限的

单 Agent 往往依赖一个很长的 **System Prompt**，把搜索、写作、代码、总结等各种能力都塞在同一个上下文里。这样会带来三个问题：**上下文受限**，信息太多后容易遗忘或相互干扰；**单点故障**，某一步出错可能导致整个任务失败；**探索深度有限**，一个 Agent 很难同时在多个方向上进行充分搜索和推理。**注意力有限**

Multi-agent的核心是**分治和压缩**，类似我们人类获取信息的过程：高熵到低熵

天然适合并行的工作流程

### 总结
**从LLM的问答，到端到端地去帮助人完成一个复杂的任务**
单agent：**工作流是灵魂，组件化是核心，记忆是纽带**
多agent：调度，执行，共享

## Function Call

>前言：大模型的能力是由什么决定的？来源于基座模型的预训练和后训练
>**预训练和后训练的质量，主要取决于模型架构设计，以及训练数据集的质量。**
>也就是说难以超出训练集以外的内容

工具调用此时便有其必要性

三大核心：**Tool list**，**结构化输出**，**工具执行返回结果**

### 工具调用
关于工具调用：两个不同的description管的内容不一样：
一个是工具本身的描述，一个是参数的描述

### 为什么仅仅加入了toolist，LLM就学会了调用工具？

工具调用的本质并不是 LLM 真正会执行工具，而是 LLM 根据 tool list 判断该调用哪个工具，并生成包含函数名和参数的结构化文本。 tool list 会把可用工具的名称、功能描述和参数格式提供给模型，真正的函数执行则由外部程序完成。 因此，Tool Calling 本质上仍然是 Prompt + 结构化文本生成 + 外部函数执行。
甚至不使用 API 中专门的 tools 参数，也可以直接把工具说明写进 System Prompt，并要求模型按固定 JSON / tool call 格式输出，实现类似效果

---
**只有理解 Function Call / Tool Calling 的底层本质，才能知道 Agent 的性能瓶颈在哪里，并有针对性地优化工具描述、Prompt、参数设计和调用流程，从而提升整个 Agent 的表现。**

>现在很多大模型都会专门针对 Tool Calling 进行后训练强化，因为随着 Agent 变得越来越重要，模型能否准确理解 tool list、正确选择工具并生成正确参数，已经成为 Agent 系统性能的关键因素之一。 因此，近来的模型通常会专门加强工具调用相关训练，以提高 工具选择准确率、参数生成准确率和调用成功率。

**不是工具越多越好，最简单的系统来达到最好的效果**
**从业务场景出发去设计整个架构，流程不要YY**

## 到一个新的场景如何设计一个agent？

1. **Simple Workflow（Prompt Chain）**：把复杂任务拆成多个步骤，每一步分别调用一次 LLM，并使用不同的 Prompt，前一步的输出作为后一步的输入，最终链式得到结果。
2. **ReAct / Reflection**：让模型按照 Thought-> Action -> Observation 的方式循环完成任务，更适合需要动态决策和工具调用的场景。
3. **Multi-Agent**：由多个 Agent 分工协作，通常采用 **Orchestrator + Workers（调度者 + 执行者）** 架构，由调度者拆解和分配任务，多个 Worker 并行执行，再统一汇总结果，Deep Research 就属于这一类。使用调度器和数据库进行数据传输

### 主流开发框架
>实际用哪一个不要纠结，专注于agentflow搭建的思想

#### LangChain & LangGraph（行业标准）

* **定位：** 控制力最强。
* **核心概念：** Graph（图）。

  * LangGraph 是目前的趋势。它将 Agent 的流程定义为一张图（Nodes 是 Agent，Edges 是跳转条件的逻辑）。
  * 它允许你构建**有环**的流程，例如：测试不通过 → 回退给程序员 → 再测试。
* **适用场景：** 生产环境、复杂的企业级应用、需要精确控制每一步流转的场景。

#### AutoGen（微软出品）

* **定位：** 对话即开发。
* **核心概念：** Conversation（对话）。

  * 在 AutoGen 中，你定义几个 Agent，然后让它们**互相聊天**。
  * UserProxy Agent（代表用户）和 Assistant Agent（AI）可以在对话中自动执行代码。
* **适用场景：** 代码生成任务、数据分析、快速原型验证。它的“多 Agent 辩论”功能非常强大。

#### Coze / Dify（低代码/无代码平台）

* **定位：** 小白神器，可视化编排。
* **核心概念：** **Workflow（工作流）**。

  * 通过拖拉拽的方式，将 LLM、插件（工具）、判断逻辑连接起来。
* **适用场景：** 非技术人员、产品经理快速验证想法、简单的客服 Bot。
