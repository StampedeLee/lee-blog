# Text-to-SQL 优化思路

## 1. 建立评估体系

首先要有一套稳定的 测试集 / Benchmark，持续评估当前 Text-to-SQL 系统的准确率，并基于评估结果迭代。

核心是先回答：

当前 SQL 到底哪里错、错多少、哪些类型最容易错？

## 2. 做前置与 Prompt 层面的优化

在不改模型本身的前提下，先通过工程和提示词提升效果，例如：

多表场景下先做 Schema / Table 筛选
控制查询或嵌套复杂度
根据评估结果优化 Prompt
增加 Few-shot 示例
减少无关表、字段和上下文，降低模型判断难度

核心思路是：

先缩小问题空间，再让模型生成 SQL。

## 3. 增强 Base Model 的 SQL 生成能力

如果前面的工程优化仍然无法满足要求，就需要进入 后训练阶段：

SFT：用高质量 Text-to-SQL 数据监督微调
强化学习 / GRPO：根据 SQL 执行结果给予奖励

SQL 很适合做强化学习，因为结果容易验证：

SQL 执行结果正确 → Reward = 1
SQL 执行错误     → Reward = 0

也可以通过标准答案（GT，Ground Truth）或执行结果来判断生成 SQL 是否正确，从而进一步强化模型的 SQL 能力。
