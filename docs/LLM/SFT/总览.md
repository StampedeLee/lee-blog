## 预训练与 SFT 的区别

预训练和 SFT 在底层训练流程上非常相似，都是通过 **Next Token Prediction** 计算 Loss 并更新参数。两者的主要区别可以概括为三个方面：

### 1. 数据格式不同

- **预训练**：使用大规模连续文本进行训练，数据本身不需要明确的问答结构。
- **SFT**：需要将数据构造成具有明确指令关系的 **QA / Instruction 格式**。
- SFT 通常需要适配具体模型的 **Chat Template**，不同模型的模板可能不同。
- 模板中的特殊 Token 用于区分 System、User、Assistant 以及对话结束位置。


### 2. Loss 计算方式不同

- **预训练**：通常对整个输入序列中的大部分 Token 都计算 Loss。
- **SFT**：通常只计算模型回答部分，即 **Completion 部分的 Loss**。
- User 输入、System Prompt 等内容一般通过 **Mask** 屏蔽，不参与 Loss 计算。


### 3. SFT 需要更加关注泛化与过拟合

- 预训练数据规模非常大，而 SFT 数据通常相对有限。
- 因此 SFT 更容易出现过拟合问题。
- 可以使用 **NEFTune** 等方法提升泛化能力。
- NEFTune 的核心思想是在输入 Embedding 上加入一定范围的随机噪声，使模型不只拟合单一精确表示，而能学习附近的语义空间。
- 噪声通常会根据 Embedding 维度进行缩放，例如：

```text
Noise Scale ∝ α / √d
```

这样可以减弱 Embedding 维度大小对噪声强度的影响。

---

>过拟合（Overfitting）是指模型在训练集上的表现持续变好、训练损失继续下降，但在评测集或验证集上的表现反而变差、损失上升。

### NEFTune 简要总结

欧式距离会随着向量维度增加而增大：

\[
||x-y||_2=\sqrt{\sum_{i=1}^{d}(x_i-y_i)^2}
\]

如果每一维的扰动大小相近，则总体距离大约与 \(\sqrt d\) 成正比。

NEFTune 在 SFT 训练时给 Embedding 加入随机噪声：

\[
X' = X + \frac{\alpha}{\sqrt{L\times d}}\epsilon
\]

其中：
- \(L\)：序列长度
- \(d\)：Embedding 维度
- \(\alpha\)：噪声强度
- \(\epsilon\)：随机噪声

除以 \(\sqrt{L\times d}\) 是为了避免序列越长、维度越高时总体噪声过大，使噪声强度保持相对稳定。

**核心作用：通过给 Embedding 加小幅扰动，减少模型对训练数据的死记硬背，从而缓解过拟合、提高泛化能力。**

**promp 的质量和多样性也是远远高于数量的数量级**

### SFT / 微调项目的简历建议

不要只写：

> 微调了 Qwen-14B，准确率提升 XX%

这种描述过于简单，无法体现真正的项目深度。

更应该突出以下内容：

- **数据集构建**
  - 数据从哪里来：公开数据、爬虫、业务数据等
  - 如何清洗、去重、过滤低质量样本
  - 如何设计数据格式与对齐方式

- **数据质量与多样性**
  - Prompt 质量和多样性通常比单纯追求数据量更重要
  - 说明如何控制数据分布，避免数据过于单一

- **合成数据**
  - 使用多种方式生成合成数据
  - 扩充不同领域、不同任务、不同表达的数据
  - 减少数据 Bias，提升模型泛化能力

- **方法依据**
  - 可以参考论文中的数据构建、筛选、合成方法
  - 在简历中体现自己不是单纯“调 API / 跑训练”，而是理解并设计了完整的数据工程流程

## 数据合成

### 合成 Prompt

1. 划分技能库，给每一条数据打上 `task type`，划分越细越好
2. 随机采样 seed，结合不同数据源中的 seed 构造新的 Prompt
   - 可以采用分层抽样
3. 使用纯指令生成 Prompt，并通过**启发式规则**进行过滤
4. 合成不同格式的数据，例如：
   - Markdown
   - JSON
   - 行文风格不同的 Prompt / Answer

### 指令参考

1. 英文数据：GPT-4 is all you need
2. 中文模型：Qwen 72B / DeepSeek MoE
3. 给定约束条件
4. 尽量加入 CoT

### 工业界做法

训练一个 Reward Model，或者使用规则拒绝采样，从生成数据中筛选出合适的 SFT / DPO 训练数据。

## 启发式规则

**启发式规则（Heuristic Rules）**：

指通过人工设计的一组经验性规则，对生成的数据进行快速筛选、清洗和过滤，而不是依赖一个复杂模型去判断。

在数据合成中，常用于过滤：

- 格式不符合要求的数据
- 长度异常的数据
- 重复或高度相似的数据
- 包含乱码、无效字符的数据
- 问答不匹配的数据
- 不符合任务约束的数据

可以理解为：

> **用人工总结出的经验规则，对生成数据做第一轮自动化质检。**
