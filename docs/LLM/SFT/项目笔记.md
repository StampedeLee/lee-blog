# Function Calling 项目笔记

## 项目梳理路径

业务场景 → 数据工程 → 训练策略 → 简历撰写

业务梳理与数据的构建直接相关

## 业务逻辑梳理

明确业务逻辑后，梳理对应的**业务流程**与**所需组件**。

1. **工作流设计**：触发逻辑 → 目标 → 调用工具。
2. **流程演练**：检查业务流程及各组件的协作是否符合预期。

>工业落地：拒答模块
>**作用**：识别并拒绝超出业务范围或缺乏可靠依据的问题，控制回答范围，降低错误回答的比例。


#### 核心两句话

1. **定义整体业务逻辑**：有多少个路由，每个路由的逻辑是什么。
2. **明确每个路由下的工作流和组件**：工作流是灵魂，组件化是核心。梳理**触发条件、目的、工具**，并进行**实景演练**。

#### 实施步骤

1. **跑通 Demo**：用 Prompt 搭建流程，让 Demo 运行起来。
2. **梳理数据形式**：明确每个业务流的数据应该是什么样子。
3. **构建种子数据集**。

## 数据工程

### 你怎么确保你的SFT能够微调出结果呢？
**答：有一套完备的数据标签，确保在这个场景中query覆盖的全面性**

### 种子数据集
定义：包含了这个场景下几乎所有的用户query和返回信息类型

数据标签：通过数据标签对数据进行分类，确保业务场景里，每一个子场景都有足够的数据

理清变量信息：
用户画像，不同标签体系下用户query，不同标签体系下tool的调用结果

初步的种子数据集是日志洗出来的

#### router 梳理
核心：定义非常详细的分支，以及分支的变量
核心：确保**本场景**query覆盖的全面性

标签体系的构建的来源是**理解场景的变与不变**

>大家要永远记得一件事情，能力永远不是模型的能力，永远是**数据**的能力
>数据沙盒构造：设计端到端数据生成 pipeline，构建包含 100 城市 + 40 用户画像 + 5 大工作流的虚拟环境；通过模板多样化（30 种问法）、槽位扰动（城市/时间/预算组合）、交互模式变换（单轮/多轮/追问）等策略，从 1,010 条种子数据扩展生成高质量训练集；实现工具调用链精确建模（顺序性 + 依赖性 + 容错性），支持旅行规划 → 攻略检索 → 天气查询、酒店推荐 → 评价获取等复杂调用序列。

### 沙盒的核心是什么？
1. 标签化体系
2. 通过可控性的数据，把原来从端到端的数据增强和构造，转化为其中某些变量的增强，更加可控，数据质量更高。
    只对定义的变量进行数据增强

这里的**“增强”指数据增强（Data Augmentation）：在已有数据的基础上，通过有规则的变化，生成更多样的训练样本。**

### 杂项
数据沙盒的核心是**构造数据**：
- 基于标签体系，覆盖不同业务分支和用户问法。
- 目标是获得覆盖广、多样性高的候选训练数据。

如果是为了获得超过原始大模型的能力，那么数据还需要人工处理
